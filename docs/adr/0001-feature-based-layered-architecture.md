# 0001. Feature-based слоистая архитектура

- Статус: Accepted
- Дата: 2026-11-02

## Контекст

Нужна структура, в которой фичи (`users`, `tasks`, `statistics`) развиваются независимо, а инфраструктура переиспользуется.

## Решение

- `internal/core/` — общий код: `domain`, `errors`, `logger`, `repository/postgres/pool`, `transport/http/*`.
- `internal/features/<x>/` — фича из трёх слоёв: `repository` → `service` → `transport`.
- Доменные модели общие и лежат в `core/domain`, чтобы фичи могли ссылаться на одни типы без импорта друг друга.
- Wiring вручную в `cmd/todoapp/main.go` через конструкторы, без DI-контейнера.

## Последствия

- Новая фича добавляется копированием структуры существующей.
- Фичи не импортируют друг друга; общее выносится в `core`.
- `core/domain` растёт со всеми фичами — это осознанный компромисс.
